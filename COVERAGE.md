# Проверка тестов и покрытия Meetly

Из корня проекта:

```powershell
npm run test:coverage
```

Команда последовательно проверяет фронтенд и бэкенд. Для бэкенда нужны настройки `backend/.env`, доступная SQL Server и применённые миграции. Интеграционные тесты создают и удаляют собственные данные; тест импорта дополнительно проверяет импорт в отдельной временной базе.

## Фронтенд

```powershell
cd frontend
npm run test:coverage
npm run typecheck
Start-Process .\coverage\lcov-report\index.html
```

Покрытие включает все `src/**/*.ts` и `src/**/*.tsx`, в том числе стили. Исключены только декларации типов `.d.ts`. Файлы, состоящие из типов или переэкспортов, могут отображаться с нулём исполняемых команд: они не увеличивают знаменатель общего покрытия.

Отчёты: таблица в терминале, `coverage/lcov-report/index.html`, `coverage/lcov.info`, `coverage/coverage-summary.json` и `coverage/coverage-final.json`.

Минимальные общие показатели, при недостижении которых команда завершается с ошибкой: 94% команд, 85% ветвей условий, 90% функций, 95% строк.

Проверяются интерфейс, переходы между экранами, контроллер, сессии и повтор запросов, загрузка байтов файлов, системный выбор фото и вложений, экспорт ICS, обмен сообщениями с картой и обработка ошибок. Внешние API и системные возможности телефона в этих тестах заменены контролируемыми ответами. Реальную работу разрешений iOS, сети телефона, галереи, браузера, звонков и меню отправки нужно дополнительно проверять на устройстве.

## Бэкенд

```powershell
cd backend
npm run test:coverage
```

Команда собирает TypeScript и запускает все `test/*.test.cjs` со встроенным покрытием Node.js. Отчёт включает код `dist/**/*.js`; в нём присутствуют и вспомогательные функции, добавленные компилятором TypeScript. Проценты строк и функций этого отчёта относятся к собранному JavaScript.

Минимальные общие показатели: 90% строк, 80% ветвей условий, 85% функций.

Проверки без работающей SQL Server:

```powershell
npm run test:unit
```

В них входят правила предметной области, валидация и её граничные значения, транзакции, обработка ошибок, JWT, редактирование встреч, подбор мест, запуск и остановка сервера, HTTP-слой с контролируемыми сервисами, фотографии и изображения карты. Полный набор дополнительно проверяет настоящую БД и HTTP API. Тест исходного снимка каталога пропускается, если исходные выгрузки отсутствуют; для его запуска нужны файлы от `catalog:fetch` и данные последнего `catalog:import`.

Процент покрытия показывает выполнение кода, а не отсутствие ошибок. Для каждого нового поведения нужны проверки результата и отказов, а не только вызов функции.

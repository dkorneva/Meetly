# Meetly

Мобильное приложение для организации встреч, выбора заведения голосованием и общения участников. Клиент: React Native, Expo, TypeScript. Сервер: Express 5, Prisma, Microsoft SQL Server.

## Структура проекта

```text
Meetly/
  frontend/  React Native, Expo и клиентские тесты
  backend/   Express, Prisma, SQL Server и серверные тесты
  docs/      общая документация
```

У каждой части свои package.json, package-lock.json, node_modules и .env. Команды обслуживания выполняются из папки соответствующей части. Корневой package.json предоставляет общую команду `npm start` для запуска обеих частей; дополнительных зависимостей у него нет.

## Запуск на этом компьютере

База `Meetly` уже создана в локальном экземпляре `SQLEXPRESS`, миграции применены. Локальные `.env` настроены отдельно от Git. Аккаунты и встречи нужно создавать самостоятельно: демонстрационных записей в приложении нет.

Для одновременного запуска выполните в корне проекта:

```bat
cd /d "D:\4 КУРС\7 семестр\Разработка моб. приложений\Лабораторные\Meetly"
npm start
```

Команда `npm run start` равнозначна `npm start`. Выполняйте её во встроенном терминале VS Code: бэкенд (TypeScript без предварительной сборки) и Expo запускаются в текущем терминале без отдельных окон. Вывод обоих процессов виден вместе, клавиатурой управляет Expo. Одно нажатие `Ctrl+C` останавливает оба процесса; если один завершится или упадёт, второй также будет остановлен. `start.cmd` оставлен как обёртка над тем же скриптом и тоже не создаёт дополнительных окон.

Перед первым запуском установите зависимости и подготовьте БД по командам ниже. SQL Server должен быть запущен. Скрипт не устанавливает зависимости и не применяет миграции автоматически. Команда `npm start -- --check` проверяет зависимости обеих частей без запуска серверов. Выполнять `npm install` в корне проекта не требуется.

Откройте два окна **командной строки Windows (`cmd.exe`)**. Команды ниже предназначены для CMD. `cd /d` одновременно переключает диск и папку, кавычки нужны из-за пробелов в пути. Строки с `REM` — комментарии.

```bat
REM Окно 1: сервер
cd /d "D:\4 КУРС\7 семестр\Разработка моб. приложений\Лабораторные\Meetly\backend"
npm ci
npm run db:generate
npm run db:migrate
npm run build
npm start
```

```bat
REM Окно 2: мобильное приложение
cd /d "D:\4 КУРС\7 семестр\Разработка моб. приложений\Лабораторные\Meetly\frontend"
npm ci
npm start
```

Оба окна оставьте открытыми. Для остановки нажмите `Ctrl+C`; если CMD запросит завершение пакетного файла, подтвердите его. Установку зависимостей и генерацию Prisma выполняйте при остановленном сервере.

При последующих запусках без изменения зависимостей и схемы базы достаточно в первом окне перейти в папку `backend` и выполнить `npm start`, во втором — перейти в папку `frontend` и выполнить `npm start`. После изменения серверного кода перед запуском выполните `npm run build` в папке `backend`.

Чтобы посмотреть IP компьютера и открыть настройки, в отдельном окне CMD выполните:

```bat
cd /d "D:\4 КУРС\7 семестр\Разработка моб. приложений\Лабораторные\Meetly"
ipconfig
notepad "frontend\.env"
notepad "backend\.env"
```

В выводе `ipconfig` найдите IPv4-адрес активного подключения Wi-Fi или Ethernet.

Телефон и компьютер должны находиться в одной сети. В `frontend/.env` переменная `EXPO_PUBLIC_API_URL` должна содержать адрес компьютера, например `http://192.168.1.127:3000`. В `backend/.env` укажите тот же адрес в `PUBLIC_URL`: он используется для ссылок на вложения. При смене IP обновите оба файла и перезапустите сервер и Expo. `localhost` на телефоне означает сам телефон.

Проверьте с телефона `http://АДРЕС_КОМПЬЮТЕРА:3000/api/health`. Если адрес недоступен, проверьте сеть и доступ к порту 3000 в брандмауэре. Для разработки на локальной сети используется HTTP; при размещении сервера в интернете нужен HTTPS.

В браузерной версии на порту Expo 8081 (или 19006) API автоматически выбирается на том же хосте, порт 3000. Например, страница `http://localhost:8081` обращается к `http://localhost:3000`. Для телефона продолжает использоваться `EXPO_PUBLIC_API_URL`. После изменения `.env` перезапустите Expo; после изменения серверного `.env` перезапустите бэкенд. В `WEB_ORIGINS` перечислите разрешённые адреса страницы через запятую, если открываете её по IP компьютера.

Используйте совместимую с Expo SDK 58 версию Expo Go либо development build. Изменение схемы приложения `meetly://` требует новой native-сборки. В Expo Go надёжно проверяется добавление участника по email; собственные ссылки приглашения предназначены для установленной сборки Meetly. Новые native-модули должны присутствовать в используемой сборке.

Описание сценариев и устройства сервера: [документ для защиты](docs/architecture.md). Запуск на другой машине: [настройка сервера](backend/README.md).

## Что делает приложение

- Настоящие регистрация, вход, выход и обновление сессии.
- Создание встреч и отдельные предпочтения участников. Организатор меняет общие параметры; каждый участник — собственные бюджет и кухни.
- Добавление зарегистрированных пользователей по email и ссылки приглашений со сроком действия.
- Настоящая OpenStreetMap-карта; локальный каталог 200 ресторанов OSM внутри Садового кольца, фильтры кухни, среднего чека и режима работы.
- Подбор настоящих заведений локального каталога и подбор по предпочтениям группы, предложение вариантов, один изменяемый голос на участника, выбор победителя.
- Отдельный чат встречи, история с постраничной загрузкой, реакции, JPEG/PNG/WebP, PDF и TXT до 10 МБ.
- Подтверждение брони организатором после связи с заведением и отмена подтверждения.
- Выгрузка ICS для ручного импорта в Яндекс Календарь; локальное напоминание за 30 минут на мобильном устройстве.
- Профиль, аватар и настройки оформления, сохраняемые на сервере.

Приложение не отправляет запрос бронирования в систему ресторана: по исходному сценарию организатор звонит сам и подтверждает результат. Внешний сервис бронирования не подключён.

Время встреч вводится по Москве и сохраняется в UTC. ICS содержит стабильный UID, московское время, переведённое в UTC, и длительность 2 часа по умолчанию. Настройка напоминаний добавляет также `VALARM` в экспортируемое событие; обработка напоминания импортированного файла зависит от календаря. Импорт файла в Яндекс Календарь выполняет пользователь.

В форме встречи время выбирается двумя отдельными списками: часы 00–23 и минуты 00–59. Район и расстояние не задаются и не участвуют в подборе.

## Источники данных

В каталоге SQL Server — 200 настоящих ресторанов OpenStreetMap внутри Садового кольца. У всех заполнены средний чек, адрес, координаты, кухня, телефон, сайт и часы работы. Средние чеки получены через JSON API Restorating с сопоставлением конкретного филиала по названию и координатам. В БД сохраняются источник, дата и расстояние сопоставления. Геометрия кольца взята из отношения OSM 2094267.

Поиск и фильтры работают по БД без запросов Geoapify, OSM или Restorating во время использования приложения. Обычная вкладка карты показывает весь каталог, переход из карточки встречи — только её варианты с коралловой меткой выбранного ресторана. Основа карты — OpenStreetMap через Geoapify (стиль Positron), отрисовка Leaflet. Для фона нужен GEOAPIFY_API_KEY в backend/.env; бесплатный план ограничен квотой провайдера. Поиск ресторанов ключ не использует. Фотографии условные, встроены в приложение и отмечены в карточках; интернет для их загрузки не требуется.

Первичное заполнение БД из сохранённых источников: `npm run catalog:import` из `backend`. Обновление внешнего снимка по желанию: `npm run catalog:fetch`, затем повторный импорт. Отсутствующие в новом снимке заведения удаляются. Если они связаны со встречами или голосами, импорт отменяется до изменения данных, чтобы сохранить историю. Данные являются снимком источников и не гарантируют неизменность цен и контактов после выгрузки.

[Полная структура БД, происхождение данных и команды импорта](docs/restaurants-catalog.md).

## Проверки

```bat
cd /d "D:\4 КУРС\7 семестр\Разработка моб. приложений\Лабораторные\Meetly\frontend"
npm run typecheck
npm run check:fsd
npm test
npm run export:web
cd /d "D:\4 КУРС\7 семестр\Разработка моб. приложений\Лабораторные\Meetly\backend"
npm test
```

Серверные интеграционные тесты выполняют настоящие HTTP-запросы, работают с SQL Server и проверяют Socket.IO. Они создают изолированные тестовые записи и удаляют их в `finally`; запускать следует на локальной тестовой/учебной базе. Фикстуры существуют только в тестах и не импортируются приложением.

Проверки импорта и миграций автоматически создают отдельные базы `Meetly_test_<случайный ID>` на том же SQL Server и удаляют их после выполнения. Для них учётной записи из `DATABASE_URL` нужны права создания и удаления баз. Рабочий каталог при этих проверках не меняется: тестовые снимки хранятся во временной папке, которую скрипт импорта получает через `CATALOG_DIR`.
